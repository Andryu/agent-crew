# 引き継ぎパケット（handoff packet）仕様 v1

**目的**: 使用量の上限・障害・コスト最適化のためにハーネス（Claude Code / Codex / Hermes / Prime）を
交代するとき、**会話履歴を渡さずに作業を継続する**ための最小の受け渡し単位を定める。

## なぜ会話履歴を渡さないのか

- 別ハーネスへ移ると会話履歴は構造的に消える（形式が違う・セッションが別物）
- 同一ハーネス内でモデルだけ替えても**プロンプトキャッシュは必ず失効する**
  （Anthropic は `/model` 切替でキャッシュがリセットされると明記。Hermes の fallback も
  プロバイダが変わるため同様）
- 実測では入力トークンの 96% が cache_read。つまり**会話を引き継ごうとすると、
  引き継いだ瞬間に全部を再送することになり最も高くつく**

→ したがって渡すのは会話ではなく **「作業状態」**。数千トークンで済み、どの向きの交代にも耐える。

## パケットの置き場所

```
docs/handoff/<UTC timestamp>-<slug>.md   （リポジトリ内。git 管理下に置く）
```

## 書式（この6節を必ず埋める。空でも「なし」と書く）

```markdown
# handoff: <slug>
- from: <harness>/<model>   例: claude-code/opus
- at: <ISO8601>
- reason: <quota|error|cost|handover>

## 1. 目的
このタスクで達成しようとしていること。1〜3行。**受け側が最初に読む唯一の文脈**。

## 2. 現在地
- HEAD: <commit sha または "未コミット">
- 変更済みファイル: <パスと、それぞれ何をしたか1行>
- 動作確認済みのこと: <実行したコマンドと結果>

## 3. 次の一手
受け側が最初に打つべき具体的な操作。ファイルパスとコマンドで書く。
「〜を検討する」ではなく「〜を実行する」の粒度。

## 4. 未決事項
判断が保留になっている論点。**受け側はここに触れてはいけない**（触るなら人間に確認）。
なければ「なし」と明記（空欄は「検討していない」と区別がつかない）。

## 5. 検証方法
完了を判定するコマンド。受け側はこれが通るまで作業する。

## 6. 落とし穴
試したが失敗した方法、環境固有の罠。受け側が同じ穴に落ちないための情報。
```

## 原則

1. **成果物で引き継ぐ**。「会話の中にしかない情報」を作らない。plan・queue・git 差分・
   テストがあれば、パケットは薄くて済む
2. **受け側は疑ってよい**。パケットの記述とリポジトリの実態が食い違ったら、実態を優先し、
   その旨を次のパケットに書く
3. **1画面に収める**（目安 2,000 トークン以内）。長いパケットは「会話を渡そうとしている」兆候
4. 交代のたびにパケットは**追記でなく新規作成**。履歴が残る
