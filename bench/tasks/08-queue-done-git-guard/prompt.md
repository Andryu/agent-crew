# タスク: タスク完了時に未コミットの成果物を取りこぼさないようにする

`scripts/queue.py` はスプリントのタスクキューを操作する CLI で、`done` サブコマンドで
タスクを DONE にする。セッションが途中で切れて、まだコミットしていない成果物が
消える事故が続いたので、`done` の時点で気づけるようにしたい。

## やること

- `done` の実行時、対象リポジトリの作業ツリーに未コミットの変更があれば
  **stderr に警告を出す**。警告には**未コミットの変更が何件あるか**を数字で含める。
- 対象リポジトリは、**キューファイル（環境変数 `QUEUE_FILE`）の置かれている場所**から
  解決する。`done` を実行したときのカレントディレクトリがどこであっても、
  判定結果が変わってはいけない。
- 未コミットの変更が無いときは警告を出さない。
- 警告はあくまで注意喚起なので、`done` 本体の成否には影響させない。
  キューファイルが git 管理下に無い場合や、`git` コマンドが使えない環境でも、
  `done` はこれまでどおり成功して終了コード 0 で終わる。
- この振る舞いを確かめるテストを `tests/` に追加する。

## 受け入れ基準

- 未コミットの変更があるリポジトリのキューに対して `done` すると、
  stderr に件数付きの警告が出て、終了コードは 0、タスクは DONE になる。
- 変更が無ければ stderr には何も出ない。
- カレントディレクトリを対象リポジトリの外（別のリポジトリや git 管理外の場所）に
  移しても、判定結果は変わらない。
- git が使えない状況でも `done` は成功する。
- `tests/test_queue_py.py` の既存テストがすべて通る。
