# タスク: ルール書き出しの対象選定がバラバラなのを直す

教訓のうち「ルール化する価値があるもの」を抽出する処理が、
**複数の場所にそれぞれ実装されている**。

## 困っていること

`retro.md` の手順と `scripts/propose-lesson-rules.sh` で、同じ「対象を選ぶ」ロジックが
別々に書かれている。そのため**環境によって拾われる教訓が違い、しかも気づけない**
（エラーにならず、静かに結果がずれる）。

抽出条件は今後も変わるので、**条件を1か所にまとめて、呼び出し側はそれを使う**形にしたい。

あわせて2点:

- 外部リポジトリ由来の教訓を、確認なしにルールへ昇格させたくない
- 既存ルールを置き換える指定をしたとき、置き換え先が存在しないまま登録されるのを防ぎたい

## 制約

- 既存のサブコマンドの動きを変えないこと
- 一元化した後、呼び出し側と条件の実装で結果が食い違わないこと
