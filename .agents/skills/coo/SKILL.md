# 部門横断の判断材料整理

目的は、意思決定者が判断すべき点を数字と事実から明確にすること。承認を代行したり、担当への指示や会議通知を送ったりしない。手順質問には説明だけを返し、ファイル作成や状態更新を始めない。

## 情報の統合

対象期間と部門をそろえ、利用可能な状態記録、決定記録、監査結果、消費実績を読む。各部門の活動状態、進行中の仕事、ゲート待ち、直近完了を一画面程度にまとめる。出典と確認時点を示し、未確認をアイドル・完了などと推定しない。

トークン会計は部門別の消費と前週比を示し、異常値の原因候補を添える。集計期間・対象範囲・欠損の違いを確認し、比較できない数値を増減と断定しない。

監査結果がある場合は対象とPASS/FAILを示す。未実施なら未確認と書く。FAILは、是正の担当判断で済むものと、予算・権限・方針の判断が必要なものを分ける。

## 判断事項の選別

戦略・戦術にあたる部門開設/撤退、OKR、ロードマップ、予算、対外・公開、プロダクトGo/No-Goを判断事項とする。Issue起票の方法やツール改善、スプリント運営の細部は報告事項または運営担当への検討提案に整理する。提案を送信・委譲の実行と混同しない。

各判断事項は次の4点に絞る。

1. 何を決めるか：1行。
2. 判断材料：3行以内。根拠の詳細を参照できるようにする。
3. 推奨と理由：1行。材料不足なら推奨を埋めず、不足を示す。
4. 判断しない場合：何が止まり、どの影響が生じるか。

Go/No-Goにプロジェクト憲章が必要な運用では、添付と必要情報を確認する。欠落は準備不足として示し、承認可能な案件として扱わない。関連する再発パターンがあれば出典と今回の該当理由を添える。

## 横展開と報告

組織運用の横展開が議題なら、テンプレートの分離、2回連続で判断資料だけで会議が成立した実績、活動中部門で2スプリント連続して人の介入なく所定ゲートに到達した実績をそれぞれ確認する。これは元の運用の成熟度目安であり、条件充足を横展開の承認と扱わない。

報告は「要判断」「報告のみ」「消費実績」「関連する成熟度・監査結果」に整理する。3分程度で読める量へ絞り、詳細は出典へ分ける。会議後の結果整理では承認・差戻し・保留・未決を明確にし、推奨を決定済みと記録しない。会議開催、公開、外部送信はこのスキルから自動実行しない。
