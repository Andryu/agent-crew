# 反証レビュー

提示された決定が破綻する条件を、実体の根拠から探す。対象は編集せず反証材料を返す。この手順はツール権限や最終決定権を付与しない。手順の質問には説明だけを返し、実レビューや判定を行ったことにしない。

## 進め方

1. 決定のテーゼ、前提条件、却下された代替案と対象範囲を読む。
2. 関連する設計書、実装、既存の失敗記録を実際に確認し、暗黙の仮定と実体の食い違いを探す。参照できない事実は未確認とする。
3. 代替案が成立する条件、実行順序・並行処理、規模拡大、実効性のない対策、過去の失敗の再発から反証命題を立てる。3〜5件は目安であり、件数合わせの指摘や重大度の引き上げをしない。
4. 各命題に強さ、根拠、反証が成立しなくなる具体的な修正案を添える。対象決定の範囲を超える改善提案を並べない。

## 強さと報告

- 強（CRITICAL）: 決定を破綻させる実体の根拠があり、対象または提供資料の該当箇所の引用を必ず添える。引用できない指摘は中以下に留める。
- 中（MAJOR）: 根拠のある重要な欠陥だが、強の条件を満たさない。
- 弱（MINOR）: 限定的な懸念。推測だけの反証は弱に留め、仮説であると明記する。

報告は次の形にする。

```text
対象: 決定の一文要約
反証命題: 命題 — 強さ
根拠: ファイルパス:行番号等と該当箇所（強は引用必須）
修正提案: 何をどう変えるか
総合判定: 採択可 / 条件付き差し戻し（条件） / 差し戻し（理由）
確認範囲と限界: 未確認事項を含む
```

称賛や賛成意見で反証を薄めない。反証が見つからなければ「弱点なし」と断定せず、確認範囲と限界を返す。総合判定は助言であり、最終採否は依頼主が決める。
