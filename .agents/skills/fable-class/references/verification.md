# 検証と完了

関連するテスト、静的検査、実行確認を変更に応じて選ぶ。成功したコマンドと結果、未実施の確認、既知の制約を記録する。queueやhookの判定は実テストと独立レビューの代わりにならない。

権限、外部副作用、データ送信境界、後方互換性、金融計算の意味を変える変更では、仕様準拠と品質を別々の新規コンテキストで確認する。対象差分、受入条件、実際の検証結果をレビュアーへ渡す。重要な設計判断は確定前に独立反証する。その他の変更はriskに応じて独立レビューを選ぶ。レビュー不能なら未レビューと記録し、必要なレビューを完了扱いしない。

指摘は実ファイル・テスト・仕様と照合して採否を決める。差戻し後は修正箇所に関係する検証とレビューを再実施する。形式上の一律回数上限で未解決の欠陥を完了扱いしない。作業が中断した場合は目的、現在地、次手、承認待ち、再検証方法を引継ぎに残す。
