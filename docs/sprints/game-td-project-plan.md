## 0. 実行方針の前提（本計画の判断事項）

1. **PR #185（文書）は先に `main` へマージする**。以降の実装スプリントは `main` からの通常のスプリントブランチで進める（長寿命の `feature/game-ideation` にコミットを積み続けない）。
2. **ゲーム本体の実装は「1タスク・1エージェント集約」の設計原則（design.md ミニADR）を、逐次4チェックポイントに分解して適用する。** 16日相当の実装を単一タスクにまとめると、既知の失敗パターン#3（サブエージェント無応答停止＝長い実装指示によるコンテキスト超過、Sprint-08/09で連続発生）を再現するリスクが高い。密結合コンポーネントの**並列**生成を避けるというADRの本来の狙いは、Riku 1人が**逐次**チェックポイントを積み上げる（各チェックポイントの開始時に前チェックポイントのコードを読んでから続きを書く）ことでも満たされる。チェックポイント区分は設計文書のD1-3/D4-8/D9-12/D13-16に対応させる。
3. Riku担当のLタスクはスプリント当たり1件の上限（Issue #78）を各チェックポイントで満たす設計にした。
4. スプリント進行中のタスクレベル指示は**全てYuki経由に一本化**する（Sprint-27最重要教訓・Issue #155）。team-lead/オーナーからの直接の実装指示があった場合もYukiが受けて再委譲する。
5. 完了・QA承認済みタスクへの無断な仕様追加は禁止（Issue #159）。v1.5/v2候補は本計画のゲート（後述）を通った上で新規タスクとして起票する。
