# 週次経営会議プロトコル v1.0

> 目的: オーナー（CEO）の稼働を「作業」から「判断」に純化する。
> 所要時間の上限は **60分**。60分で終わらない会議は Rin の準備不足として改善対象になる。

## 開催

| 項目 | 内容 |
|------|------|
| 頻度 | 週1回（休日）。スキップした場合は翌週冒頭で必ず「スキップした」事実を議事録に残す |
| 参加 | オーナー + Rin（参謀長）。必要に応じて Yuki（PM）の報告を Rin が代読 |
| 事前準備 | Rin が意思決定キュー（`docs/org/council/YYYY-MM-DD-queue.md`）を生成しておく |
| 監査スキャン | Rin が `scripts/audit-scan.sh --out docs/org/audit/YYYY-MM-DD-audit.md` を実行し、FAILがあれば意思決定キューの「要判断」に追加する |

## 議事次第（60分）

| 時間 | 内容 | 担当 |
|------|------|------|
| 0-5分 | 前回の判断事項の実行状況（やると決めたことは実行されたか） | Rin |
| 5-30分 | **意思決定キューの処理** — Go/No-Go・リリース・支出・権限をひとつずつ判断 | オーナー |
| 30-40分 | 部門状態ボード（アクティブ部門の進捗、アイドル部門の蓄積状況） | Rin |
| 40-45分 | トークン会計（部門別消費・前週比・異常値） | Rin |
| 45-50分 | 教訓レビュー（今週の新規教訓と、想起すべき再発パターン） | Rin |
| 50-55分 | 横展開トリガーの充足状況（①テンプレート ②会議2連続 ③スプリント2連続） | Rin |
| 55-60分 | 来週のフォーカス宣言（1行） | オーナー |

## ルール

1. **判断はキューにあるものだけ。** 会議中に新しい議題を持ち込まない（持ち込みたくなったら来週のキューへ）。
2. **判断の記録**: 各項目の結論（承認/差戻し/保留）と一言理由を、キューのファイルに直接追記して確定させる。
3. **保留は2回まで。** 同じ項目を3回保留したら、それは「No」であるとみなして差し戻す。
4. **教訓の想起**: レトロで記録した教訓のうち、今週の判断に関係するものを Rin が必ず読み上げる
   （「記録するが想起されない」失敗パターンへの構造的対策）。
5. 会議の成立条件は「意思決定キューだけで回ること」。オーナーがキュー外の状況把握のために
   ログやコードを直接掘る必要があった場合、その会議は**不成立**とカウントする（横展開トリガー②の判定基準）。
6. **キューの抽象度は戦略・戦術レベルに限定する**（2026-08-02 オーナー決定）。載せてよいのは
   部門の開設/撤退、OKR・ロードマップの変更、予算・支出、対外・公開、プロダクトの Go/No-Go。
   実行方法（How）に属する運営判断（Issue 起票、ツール改善、スプリントスコープの機微など）は
   team-lead に委任し、キューには「報告のみ」節で共有する。オーナーのレビュー対象は戦略と戦術であり、
   How のレビューは QA・team-lead が担う。

## 成果物

- 判断結果が追記された意思決定キュー（そのまま議事録を兼ねる）
- 判断事項は Rin が該当部門の PM（Yuki）へ翌営業処理で伝達する
