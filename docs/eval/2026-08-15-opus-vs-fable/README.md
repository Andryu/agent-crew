# Opus 5 vs Fable 5 比較実験（2026-08-15、ADR-017 の裏付け）

**目的**: team-lead を Fable 5 → Opus 5 に切り替えたときの実務品質差を、同一プロンプト・フレッシュコンテキスト・同時刻で測る。
**方法**: 3課題 × 2モデル（`Agent` ツール、`model: opus` / `model: fable`、general-purpose、同一プロンプト `prompts.md`）。採点は Sonnet のブラインド審査（X/Y ラベル、モデル名非開示、実体裏取り必須）＋ team-lead の読み比べ。n=1/課題。

| 課題 | 測る能力 | 勝者（審査） | 文字数（上限） | 所要 |
|---|---|---|---|---|
| T1 反証レビュー（ADR-017 v2） | 判断・穴の発見 | **Opus**（正確さ5/3、深さ5/3） | Opus 2855 / Fable 1888（1800） | Fable が約1分早い |
| T2 話者帰属のミニADR | 設計判断 | **Opus**（僅差、網羅性） | Opus 2325 / Fable 1968（2000） | Fable が約3分早い |
| T3 privacy-check.sh 修正計画 | 実体調査＋計画 | **Opus**（深さ5/3、付随発見） | Opus 4365 / Fable 3161（1800） | Fable が約2分早い |

**所見**
- 実質品質（正確さ・深さ・実害に直結する発見）は Opus が3課題とも上回った。Fable に軽微な事実誤認（存在しない行番号引用、Stop フックで握り潰される ERR trap 提案）があった一方、Opus の引用は全件裏取り一致。
- Fable は**指示遵守と簡潔さ**で一貫して優位（3課題中2課題で上限内、Opus は毎回大幅超過）。所要時間も Fable が短い。
- 両モデルが独立に同じ結論に到達した点が2つ: (1) ADR-017 v2 の残存欠陥（初回ターンの Fable モード誤注入、critic 効果指標の計測手順欠如）、(2) T2 の「3票投票」案は票が独立でないため却下すべき（証拠階層／錨方式へ）。
- **限界**: n=1、サブエージェント文脈（Fable の主戦場である長時間自律セッションではない）、審査員は Sonnet。「Opus ≥ Fable」と一般化する材料ではなく、「Opus 切替で工程品質は落ちない見込みが強い」の材料として使う。

**この実験から PR #184 に反映した修正**: model-mode.sh の fail-closed、フックの cwd 固定、PPID ロック撤去、critic の語彙統一、retro.md ステップ 2.8、ADR の symlink 前提訂正、発動基準 (c) の絞り込み、PR テンプレの plan リンク欄。Issue #186（privacy-check.sh）。
