# ゲーム企画 壁打ちメモ（2026-08-15）

ステータス: 壁打ち中（オーナー×AI）。決定事項なし。
位置づけ: 巡室（プロトタイプC）のプレイテスト判定（2026-09-30）とは独立した「次弾候補」の発散メモ。巡室の検証を薄めない。

## 前提（部門で確定済みの制約・原則）

- ブラウザ一択（Vanilla JS+Canvas / Phaser）、14日規模、localStorage完結、サーバなし
- 設計原則: **AIをコンテンツ供給者に置くと失敗し、攻略対象のシステムに置くと成功する**（LLM NPC・AI生成台詞は市場実証で不利）
- Go/No-Go指標は「2周目到達率」「継続意向」。初回体験の見栄えではなく再訪で測る
- 届け方が最大の関門（巡室の教訓）。シェアしやすさは企画段階から織り込む

## 案1: ソウルライク × ローグライク

### ジャンルの矛盾をどう解くか
ソウルライクの快感は「固定された敵パターンを死にながら暗記して克服する」こと。ローグライクは「毎回変わる」こと。素直に混ぜると暗記が効かず、ソウルの快感が消える（Nightreign型は大手だからこそ成立）。

解き方の候補:
- **A. 敵は固定、プレイヤー側だけ揺らす**（Hades/Dead Cells方式。実績あるが既に飽和）
- **B. ボスは固定パターン + ラン毎に「変奏」1〜2個**（同じ曲の別アレンジ。暗記が半分効く）
- **C. ボスがプレイヤーを学習する**（AIネイティブ。前回のランで多用した回避方向・攻撃タイミングをルールベースで記録し、次回はそこを潰してくる。「ボスに覚えられている」体験）

C が部門原則に最も忠実で、かつ他にない。「ローグライクの変化源をRNGでなく敵の適応にする」。

### 差別化フック案
- **ボスラッシュ特化**: 探索なし。ボス5体、1ランで3体+最終。ステージ制作コストを丸ごと削れる
- **死が資産になる**: 死んだ地点に前回の自分（残滓）が残り、次のランで味方の1回だけ囮になる／逆に敵に吸収されて強化される。ソウルの血痕をローグライクの継承要素に変換
- **入力を1〜2ボタンに絞る**: パリィ専用（Furi・Sekiro弾きだけ抽出）。ブラウザの入力遅延と、ソロ+AIチームで最も難しい「アクションの手触り調整」の面積を最小化する

### 14日プロトタイプ切り出し
ボス1体・3フェーズ・パリィ/回避/スタミナのみ。適応AI（C）は「直近3ランのプレイヤー行動ヒストグラム→次ランの攻撃選択重み」で実装。2周目到達率が自然に測れる。

### リスク
- **最大リスク: 手触り**。ヒットストップ・予備動作・SEを詰め切れないと「安っぽいソウルもどき」で終わる。レビューが最も辛辣なジャンル
- 適応AIが「理不尽」に感じられる境界の調整（学習させすぎると勝てなくなる）
- 市場: 2026年もパリィ系・ボスラッシュ系の新作が続く（Ricochet Raven、Nullpoint Protocol等）。「AIが学ぶ」を前面に出さないと埋没

## 案2: タワーディフェンス

### 市場観
王道TDは飽和。近年当たった個人〜少人数作は「ミニマル + 1ひねり」（Thronefall＝自分もユニット、Emberward＝テトリス壁、Nomad Defender＝デッキ構築）。2025-26はローグライトTDが売上上位に入り、Steamに専用フェスができるほどジャンルは活況＝競合も多い。ブラウザ実装との相性はジャンル中最良（Bloonsの出自はFlash）。

### 差別化フック案
- **A. 進化する攻め手（AIネイティブ本命）**: 敵ウェーブをプレイヤーの防衛配置に対して遺伝的アルゴリズム/簡易探索で生成する。「群れが自分の弱点を見つけて突いてくる」。TDの敵をコンテンツから攻略対象システムに変える。ルールベースで完結、LLM不要
- **B. 非同期対戦（届け方の武器）**: 自分の防衛配置をURL/シェアコードに圧縮し、友人が「攻め側」で挑む。サーバ不要でPvPが成立し、シェアが自然発生する。巡室で詰まった「届け方」への直接回答
- **C. テーマ**: 妖怪 vs 結界（和）／体内の免疫（敵=病原体、塔=白血球）／城攻め。Aと組むなら「学習する病原体」の免疫モノは説得力がある

### 14日プロトタイプ切り出し
1マップ・塔3種・敵1種+進化パラメータ（経路選択/速度/耐性の3遺伝子）・10ウェーブ。B のシェアコードは JSON→base64→URL で1日で載る。

### リスク
- 「進化する敵」はプレイヤーに知覚されないと価値ゼロ。進化の可視化UI（「前ウェーブから何が変わったか」）が必須
- 対人でない限りTDは長期継続が弱い（周回動機の設計が必要）
- ジャンル競合が多く、面白さの土台（配置の気持ちよさ）は最低ラインが高い

## 案3: 仮想AIを育てて上級ジョブを目指す育成ゲーム

### 部門リサーチとの関係
案D（育てるAIの子インクリメンタル）に近いが、Dが下方修正された理由は「AIが台詞や物語を供給する」前提だったため。**育成対象のAIをLLMではなく「プレイヤーが形作る方策（ポリシー）」として扱う**なら原則に反しない。むしろ最もAIネイティブ。

### コアの再定義
「AIを育てる」＝ステータスを盛ることではなく、**行動ルールを教え込むこと**。
- 育成: 訓練課題（ミニダンジョン等）でお手本を見せる／選択肢で方針を与える → AI側は模倣+ノイズで行動方策を更新（ルールベース。Carnage Heart や Gladiabots の「プログラミング育成」を、チップ組みでなく「実演と褒め方」に置き換えた形）
- 実戦: 育てたAIが**自律で**ダンジョンに挑み、プレイヤーは介入できず見守る（オートバトラー的。Loop Hero・Backpack Battles が「見るだけ」でも成立することを実証）
- ジョブ: 見習い→初級→上級の**昇格試験＝ベンチマークダンジョン**。上級は分岐（前衛/後衛/支援…）。ジョブ制の快感（RO・FFT）をそのまま借りる
- 隠し適性: 訓練の与え方でパラメータが偏り、意図しないジョブ適性が育つ（プリンセスメーカーの「思ってた子と違う」を、AI育成の面白さとして再解釈）

### 差別化フック
- **STONEFISH のブランドと同型**（AIエージェントを育てて仕事を任せる会社が作る、AIを育てるゲーム）。対外発信の物語が最初からある
- 「教え方が下手だと変な癖がつく」＝AI育成の実体験をゲームにした、という切り口はSNSで語りやすい
- 案Dの弱点だった「放置ゲーの単調さ」を、見守り→修正→再挑戦のループで回避

### 14日プロトタイプ切り出し
ジョブ深さ2（見習い→初級2択）、ダンジョン1種、教えられる行動3〜4個。「教えたことが行動に出た」瞬間が1回でも起きればプロトタイプ成功。

### リスク
- 顔のないAI育成は乾く。かわいさ／キャラクター性が必要（ここは絵素材のコストと直結）
- 「見守るだけ」が退屈に転ぶ境界（介入ゼロは危険。1ランに1回だけ声をかけられる、程度の調整余地は残す）
- コンテンツ量ゲー（ジョブ・ダンジョン）で、14日では深さを見せられない可能性

## 深掘り: 案2 TD「進化する群れ」（仮）

### 一文コンセプト
敵の群れがウェーブごとにあなたの防衛に合わせて進化する。あなたは進化を読んで配置を組み替え続ける、軍拡競争のTD。

### コアループ（1ラン 10〜15分）
1. 配置フェーズ: グリッドに塔を置く／売る（資金制）
2. ウェーブ: 群れ（20〜40体）が3レーンから侵攻
3. **進化フェーズ**: 生き残り距離・与ダメで各個体を評価 → 上位が交配+突然変異 → 次ウェーブの群れを構成
4. 変異レポート表示（「高速化 +12%」「レーンBを好むように」「火耐性を獲得」）
5. 1に戻る。15ウェーブ耐えたらクリア、以降エンドレス

### 進化モデル（ルールベース、LLM不要）
- 遺伝子は最大5つに絞る: **速度 / 体力 / 耐性種別（3属性の1つ） / レーン嗜好 / 体格（大=硬い遅い、小=速い脆い）**
- 評価関数 = 到達距離 + 拠点与ダメ×係数。上位30%を親に、交叉+各遺伝子5〜10%で突然変異
- **遺伝子を見た目に直結させる**（速度=細長い、耐性=色、体力=太い輪郭、体格=大きさ）。抽象図形なら絵素材コストほぼゼロで、進化がそのまま「見える」
- 暴走防止: 各遺伝子に上限、突然変異率はプレイヤーの塔多様性が低いほど上げる（単一戦術への罰）

### プレイヤー側の反撃手段
- 塔3種（三すくみ属性）+ 汎用1種。属性特化した群れに対して塔を組み替える＝軍拡の往復が生まれる
- 「レーン嗜好」への対抗としてレーン封鎖／誘導の壁を置ける（配置の妙）

### 届け方＝シェアコード
- v1: **チャレンジリンク**（マップseed+初期資金をURLハッシュに埋め込む）。同じ条件で何ウェーブ耐えたか競う。サーバ不要
- v2候補: 攻め手モード（相手の防衛配置をURLで受け取り、遺伝子ポイントを割り振って群れを設計し突破を狙う）。非同期PvP。14日には入れない
- 計測: 受け手側のURLパラメータ `?c=` 有無をlocalStorageに記録→巡室と同じアンケート+JSONエクスポートで回収

### テーマ候補
| テーマ | 進化との整合 | 素材コスト | 所感 |
|---|---|---|---|
| 抽象図形（Thronefall系ミニマル） | ◎ 遺伝子=見た目 | 最小 | 14日で成立させるならこれ |
| 免疫（塔=白血球、敵=変異する病原体） | ◎ 物語として自然 | 中 | 「はたらく細胞」で日本の受けも良い。抽象図形の上に薄く被せる形が現実的 |
| 妖怪 vs 結界 | △ 妖怪が「進化」する説明が弱い | 高 | ソウルライクとの世界観共有には向く |

推し: **抽象図形ベース + 免疫の薄い皮**（形・色で遺伝子を見せ、名前とフレーバーだけ免疫）。

### 14日切り出し
- D1-3: グリッド・塔3種・敵1種・15ウェーブ・資金（普通のTDとして遊べる状態）
- D4-7: 進化モデル・見た目直結・変異レポート
- D8-10: チャレンジリンク・アンケート・エクスポート（巡室から流用）
- D11-14: バランス、オーナー実プレイ2回、Pages配備
- 成功判定（プロトタイプ内）: オーナーが「群れが自分に合わせてきた」と感じる瞬間が1ランに1回以上ある

### 主なリスク
- 進化が知覚されない → 変異レポートと見た目直結で対策
- 進化が「理不尽」に振れる → 上限と突然変異率の調整幅を最初からパラメータ化しておく
- TD単体は再訪動機が弱い → チャレンジリンク（他人のスコアと比較）で補う

## 深掘り: 案1 ソウルライク（プレイヤー操作版）

### 一文コンセプト
あなたを覚えるボスと、死ぬたびに構成が変わるあなた。ボスラッシュ特化の2Dソウルライク。

### 手触りリスクを操作性を残したまま下げる設計
1. **見下ろし2D**（Hyper Light Drifter / Hades 系）。横スクロールに比べ攻撃モーションの枚数が少なくて済み、**攻撃範囲の予告表示（テレグラフ）** で読みやすさをアニメ品質に依存させない
2. **操作は4つに固定**: 移動 / 回避（無敵時間） / 攻撃 / パリィ。スタミナあり。魔法・装備・成長ツリーなし
3. **ジュース優先**: ヒットストップ・画面揺れ・白点滅・パーティクル・SE。巡室の Web Audio 合成音をそのまま流用（外部音源なし）。安いのに手触りの8割を作る
4. **手触りゲート（D3）**: ボスを作る前に「操作キャラ vs 案山子」の段階でオーナーが触り、気持ちよくなければ先に進まない。巡室の音響で学んだ「早い段階でオーナーに触ってもらう」を工程に組み込む
5. ボス1体・3フェーズ・攻撃6種（各攻撃に明確な予備動作）

### 「AIが覚える」ボス
- 記録するもの: 回避方向の偏り、回避のタイミング（早い/遅い）、攻撃を差し込む位置（コンボ終わり等）、パリィ成功率
- 反映するもの: 攻撃選択の重み（左に逃げがちなら左を巻き込む技を増やす）、ディレイ攻撃の混入率（差し込み癖を狩る）、フェイント頻度（早め回避を狩る）
- **ボスの手数自体は増やさない**（理不尽化防止）。同じ6技の「出し方」だけが変わる。プレイヤーには「読まれている」と分かるカットイン（例: 前回死んだ技をボスが構えで見せる）を入れる
- 学習は直近3ランのみ参照（永久蓄積させず、癖を変えれば脱出できる）

### ローグライク要素は最小限
- 死ぬ→再挑戦時に3択で1つ「祝福」（攻撃速度・スタミナ・パリィ窓等）。ビルドの揺らぎはこれだけ
- **残滓**（前回死んだ地点に前回の自分が残り、1回だけ囮になる）は面白いが14日では入れない。v2
- 本番構想: ボス5体、1ラン3体+最終。プロトタイプは1体

### 14日切り出し
- D1-3: 移動/回避/攻撃/パリィ、スタミナ、ジュース、案山子。**D3 手触りゲート**
- D4-8: ボス1体・3フェーズ・6技・テレグラフ
- D9-11: 学習ボス（記録→重み反映→カットイン）
- D12-14: 祝福3択、アンケート、Pages配備、オーナー実プレイ
- 成功判定: 「読まれた」と感じてプレイスタイルを変えた瞬間があるか／2周目到達率

### 主なリスク
- 手触り（D3ゲートで早期に発見する）
- 学習の理不尽感（手数を増やさない・直近3ランのみ、で抑える）
- ジャンル競合。「ボスに覚えられる」を看板にしない限り埋没

## 2本の関係

- **順序は TD → ソウルライク を推奨**。理由: (1) TD は14日で成立する確度が高く、チャレンジリンク・アンケート・Pages配備の「届け方の型」を先に固められる (2) ソウルライクは手触りのオーナー往復に時間が要り、後ろに置いた方が余裕が取れる (3) 巡室判定（09-30）前に2本重ねると回収に注意が散る
- **共有基盤**: canvasループ / 入力 / Web Audio合成音 / localStorage / アンケート+JSONエクスポート / シェアURL を `game-prototype/_kit/` に切り出して2本目から使う。ただし1本目で先に基盤を作り込まない（巡室・TDから抽出する順）
- **世界観共有は任意**。抽象図形+免疫でTDを作るなら、ソウルライクは別世界でよい（無理に揃えない）

## 次の壁打ち論点

1. 順序: TD → ソウルライク で良いか。並行を望むなら、どちらをオーナー実プレイの優先に置くか
2. TDのテーマ: 抽象図形+免疫の薄い皮、で良いか
3. ソウルライクの視点: 見下ろし2Dで良いか（横スクロールを望むなら素材コストが跳ねる）
4. 着手時期: 巡室判定（09-30）前に着手するか
