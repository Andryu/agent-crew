# ADR: fable-class — 上位モデル不在時に Opus+Sonnet で同等品質を出す工程設計

**ステータス**: 採択（2026-08-15、ADR-017 により実運用へ）
**日付**: 2026-07-20

---

## 背景

最上位モデルである Fable は、将来的に利用できなくなるリスクがある(提供終了・障害・コスト制約など、理由は問わない)。その際、オーケストレーターを Opus に差し替えるだけで品質が落ちてしまうのであれば、成果物の品質がモデルの可用性に依存してしまうことになる。

これを避けるため、品質の根拠をモデル依存からプロセス依存へ転換したい。つまり「どのモデルが使えるか」ではなく「どんな工程を強制しているか」が品質を決めるようにする。

## 決定

fable-class スキル群を導入する。構成要素は以下の通り。

- **5フェーズ工程**: SPEC → PLAN → DELEGATE → VERIFY → CONVERGE
- **モデルルーティング**: 計画・意思決定・レビュー判定はオーケストレーター(Fable、なければ Opus)、実装・テスト作成・ドキュメント執筆は Sonnet サブエージェント(フレッシュコンテキスト)、広範囲の探索は Explore/haiku
- **二段階レビュー**: 仕様準拠レビューと品質レビューを分離し、いずれも実装者・オーケストレーター以外の新規コンテキストで実施する
- **修正ループの上限2回**: 2回で収束しなければ作業を停止し、ユーザーにエスカレーションする

## 根拠となった海外の実例・知見

1. **Opus 計画 + Sonnet 実装は確立されたパターン**
   Opus で計画を立て、Sonnet で実装するという役割分担は、コミュニティで既に実践例のあるパターンである。
   https://codely.com/en/blog/how-to-use-opus-for-planning-and-sonnet-for-implementing-in-claude-code
   https://www.mindstudio.ai/blog/claude-code-advisor-strategy-opus-sonnet-haiku

2. **obra/superpowers のマイクロタスク計画・サブエージェント駆動開発・二段階レビュー**
   タスクを小さい単位に分解し、サブエージェントに委譲し、仕様準拠と品質を別々にレビューする手法が採用されている。
   https://github.com/obra/superpowers
   https://blog.fsck.com/2025/10/09/superpowers/

3. **Spec駆動開発（Spec → Plan → Tasks → Implement）**
   要求を仕様として確定させてから計画・タスク化・実装に進む流れが、成果物の一貫性を担保する手法として整理されている。
   https://thebcms.com/blog/spec-driven-development

4. **弱い検証者による無人ループの危険性と停止条件の重要性**
   検証能力の弱いレビュアーに無制限に修正ループを回させると、収束しないまま延々とトークンを消費し続けるリスクがある。明確な停止条件を設けることの重要性が指摘されている。
   https://www.aibuilderclub.com/blog/loop-engineering-guide-2026

## 却下した代替案

### Opus 単独で今まで通り作業する

工程を強制する仕組みがないため、Opus 単独では「検証しない・代替案を出さない・仕様が曖昧なまま実装する」という省略が再発する。Fable との品質差を埋める目的を達成できないため棄却。

### 全作業を Sonnet に任せて安くする

トークンコストは下がるが、計画・代替案比較・レビューの採否判断といった意思決定の質が落ちる。特に代替案の比較やレビュー指摘の採否判断は、実装作業よりも成果物の品質を左右する工程であり、ここを安価なモデルに任せるのは本末転倒であるため棄却。

## 影響

- 5フェーズ工程・二段階レビューにより、単純にモデルへ丸投げする場合と比べてトークン消費は増える。
- ただし、レビューによる手戻りや、仕様の曖昧さに起因する後工程での修正が減ることで、トータルのトークン消費・作業時間は相殺される見込みである。
- Fable が復帰した場合も、この工程自体は変更不要であり、オーケストレーターを Opus から Fable に差し替えるだけで、そのまま同じワークフローを継続できる。
