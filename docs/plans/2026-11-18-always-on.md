# plan: always-on

- **日付**: 2026-11-18
- **担当**: team-lead（設計）／実装は Phase ごとに委譲
- **complexity**: L（全体）。本 plan で確定させるのは Phase 0 と Phase 1。Phase 2 は別 plan
- **risk_level**: high（権限・無人実行・エージェント間プロトコルの方向性を含むため）
- **mode**: opus（`get_session` の `last_served_model=claude-opus-5-5`。`scripts/model-mode.sh` はクラウドでは `src=none` で Pro 側に倒れるため、実体はセッション API で確認した。ADR-017 の表 v2 に従う。critic は Kagami サブエージェント）
- **ADR参照**: `docs/adr/ADR-019-always-on-operation.md`

## SPEC

- **要求の再記述**: Anthropic の「Building always-on agents」が示す5部品（inbox / timers / memory / permissions / outbox）を agent-crew に当てはめる。owner が見ていない間も、安全に1歩ずつ進み、判断が要るものだけを owner に返す開発環境にする。前回の提案（許可の縮小、Outbox の静音化、timer、キューの正本移行、memory 整理、シグナルの修正）を、実装できる単位まで設計する。
- **暗黙の前提**:
  - 既存の工程（fable-class、critic、学習ループ、ADR-016 のフック抑制、ADR-012 の正本一箇所）を壊さない。
  - 対話運用（owner が見ているローカル／クラウドのセッション）の体験を悪化させない。
  - Claude Code と Codex の両方で動く（dual-harness、`AGENTS.md` の共通契約）。
  - 利用枠が有限（ADR-018 の Pro 運用を経験済み）。always-on は利用枠を食う。
  - repo / Git / テスト結果が真実源（`AGENTS.md`）。
- **不明点**:
  - 自己解決済み:
    - クラウドに Obsidian は無い → `ls` で確認済み。
    - `_queue.json` と `_signals.jsonl` は git 追跡下 → `git ls-files` で確認済み。
    - シグナルのスキーマずれによる KeyError → 再現済み。
    - フックのドリフト → `diff` で確認済み。
    - クラウドでの `model-mode.sh` は `src=none` → 実行して確認済み。
    - リモート判定用の環境変数 `CLAUDE_CODE_REMOTE` は存在する → ただし判定には使わず、パスの存在で判定する。
  - 実装前に確認する（T0-4 の前提条件）: Claude Code の permission ルールで `Edit(...)` のパス基点（`/x`・`./x`・`x` の違い）と、`Bash(...)` のワイルドカードが途中の位置でも効くか。**claude-code-guide に公式ドキュメントで確認させてから書く**（推測で書かない）。
  - Phase 2 の前提条件: クラウドセッションから `gh` で Issue を書けるか。
  - owner にしか決められないこと:
    1. timer の時刻と頻度（初期値: daily-brief 平日朝1回、weekly-council 週1回）
    2. main のブランチ保護を有効にしてよいか（owner の GitHub 設定作業）
    3. Slack 通知を needs-owner と result だけに絞ってよいか（既定値の変更）
- **テーゼ**: 常時稼働とは「ずっと動く」ことではなく、「状態と権限は run の外に置き、起こされた run は1歩だけ進め、owner の判断が要るものだけを返す」ことである。

## PLAN

### 代替案比較表（中心の決定: Inbox の真実源をどこに置くか）

| 案 | 複雑度 | 変更範囲 | リスク | テーゼ適合 |
|---|---|---|---|---|
| A. `_queue.json` を維持し、run が main に直接 commit | 低 | 小 | 並列で衝突、run が main に触る | **不適合**（状態が run の中、main に触る） |
| B. 状態専用ブランチ | 中 | 中（衝突リトライ） | push 競合、owner から見えない | 部分適合（git の外ではない） |
| C. 外部 DB | 高 | 大（インフラ・認証） | 運用負担 | 適合するが規模に過大 |
| **D. GitHub Issues ＋ ラベル、`_queue.json` は射影（採用）** | 中 | CLI は維持、直接 jq で読む約13本は射影で互換 | `gh` がクラウドで書けるか未検証、強制 high | 適合 |

足切り: A は不適合。B・C・D の比較では D を採用する（理由はミニADR）。

### ミニADR

- **背景**: 並列 run と無人 run を可能にするには、状態を run（ブランチ・セッション）の外に出す必要がある。ただし、エージェント間プロトコルの変更は強制 high で、前提も一部未検証。
- **決定**: ADR-019 の D1〜D7。Phase 0（土台）と Phase 1（timer ＋ 読み取り専用 run）を本 plan で実装可能な粒度まで確定する。Phase 2（Issue inbox）は方向性だけを確定し、別 plan とする。
- **理由**: Phase 0/1 だけで、許可の縮小・通知の静音化・毎朝の要約という価値が出る。しかも状態を書かないので衝突しない。書く run は Inbox が git の外に出てからにする。
- **却下案**: ADR-019「却下した案」A〜F を参照。

#### Phase 0

**T0-1 シグナルのスキーマ修正**
- **complexity**: S / **risk_level**: low
- **目的**: `task_completed.sh` が書くシグナルを `SignalEvent` スキーマに合わせ、古い行があってもレポートが落ちないようにする。
- **対象ファイル**: `.claude/hooks/task_completed.sh`、`scripts/queue.py`、`tests/test_queue_py.py`
- **変更内容**:
  1. `task_completed.sh` の `jq -n` 出力に `type: "task.completed"` を**追加**する。既存の `event`・`tool_use_id` キーは残す（bench 03 との互換のため）。
  2. `queue.py` のシグナル集計（`signals_file` を読む箇所）で `e['type']` を `e.get('type')` に置き換える（`report` 系の全箇所）。
  3. `tests/test_queue_py.py` に「`type` キーの無い行（`{"ts":..., "sprint": <現スプリント>, "event":"task_completed"}`）を含む `_signals.jsonl` でもレポートが例外を出さず、`task.done` の件数が正しい」テストを1件追加する。
- **してはいけないこと**: 既存の `_signals.jsonl` の行を書き換えない。`bench/` を変更しない。`queue.sh` の grep 集計は変更しない（`task.completed` は数えなくてよい）。
- **検証コマンド**: `uv run pytest -q tests/test_queue_py.py` → 全件 pass。`rg -n "e\['type'\]" scripts/queue.py` → 0件。

**T0-2 subagent_stop.sh のドリフト解消（正本を `hooks/` に一本化）**
- **complexity**: M / **risk_level**: medium
- **目的**: 配布元 `hooks/subagent_stop.sh` を両方の機能を持つ正本にし、稼働側 `.claude/hooks/subagent_stop.sh` をその完全なコピーにする。
- **対象ファイル**: `hooks/subagent_stop.sh`、`.claude/hooks/subagent_stop.sh`、`tests/test_hook_sync.py`（新規）
- **変更内容**:
  1. 稼働側にだけある次の2機能を、配布元に移植する。(a) スプリント完了時に `--- NEXT STEP ---` でレトロ（`Use the retro agent on "<sprint>"`）を提示するブロック。(b) 末尾の `scripts/lessons-to-vault.sh` 呼び出し（`|| true` 付き、REPO_ROOT の解決方法も含めて）。
  2. Slack 送信は配布元の `slack_notify`（`jq -n` で JSON を組む方式）に統一する。文字列連結で JSON を組む稼働側の実装は持ち込まない。
  3. 配布元をそのまま稼働側へコピーする（`cp hooks/subagent_stop.sh .claude/hooks/subagent_stop.sh`）。
  4. `tests/test_hook_sync.py` を追加する。内容は「2ファイルのバイト列が一致する」ことを assert する1テスト。
- **してはいけないこと**: 通知の条件（どのイベントで Slack に送るか）は変えない（T0-3 の担当）。`install.sh` を変更しない。
- **検証コマンド**: `diff hooks/subagent_stop.sh .claude/hooks/subagent_stop.sh` → 出力なし。`uv run pytest -q tests/test_hook_sync.py` → pass。`bash -n hooks/subagent_stop.sh` → エラーなし。`rg -n 'lessons-to-vault|Use the retro agent' hooks/subagent_stop.sh` → 各1件以上。

**T0-3 Outbox の静音化**
- **complexity**: M / **risk_level**: medium
- **目的**: Slack に送るのを needs-owner と result だけにし、エージェント個別の完了と handoff は標準出力だけにする。
- **対象ファイル**: `hooks/subagent_stop.sh`、`.claude/hooks/subagent_stop.sh`（コピーのみ）、`tests/test_subagent_stop_outbox.py`（新規）、`README.md`（Slack 通知節のみ）
- **変更内容**:
  1. 環境変数 `AGENT_CREW_SLACK_LEVEL` を導入する。値は `owner`（既定）または `all`。
  2. `owner` のときに Slack へ送るのは、BLOCKED の通知とスプリント完了（Quality Gate 通過）の通知の2種類だけ。READY_FOR_* への handoff と、エージェント個別の完了は `slack_notify` を呼ばない（標準出力の NEXT STEP 提示は従来どおり出す）。
  3. `all` のときは T0-2 完了時点の挙動と完全に同じにする（ロールバック用）。
  4. 編集後、T0-2 と同じ方法で稼働側にコピーする。
  5. テストは、`PATH` の先頭に `curl` のスタブ（引数をファイルに追記するだけのスクリプト）を置き、`SLACK_WEBHOOK_URL=http://example.invalid` で一時ディレクトリのキューに対して hook を実行する。次の3ケースを検証する。(a) `owner` ＋ READY_FOR_SORA が1件 → curl 呼び出し0回。(b) `owner` ＋ BLOCKED が1件 → 1回。(c) `all` ＋ READY_FOR_SORA が1件 → 1回。
  6. README の「Slack 通知」節に `AGENT_CREW_SLACK_LEVEL` の説明を3行以内で追記する。
- **してはいけないこと**: `pm.md` の Yuki による直接送信（スプリント開始・完了）は変更しない。新しいフックを追加しない（ADR-016）。
- **検証コマンド**: `uv run pytest -q tests/test_subagent_stop_outbox.py tests/test_hook_sync.py` → pass。
- **依存**: T0-2 の後。

**T0-4 Permissions の縮小と deny の新設**
- **complexity**: S / **risk_level**: high
- **目的**: ADR-019 D5 の「内側」を `.claude/settings.json` に反映する。
- **前提条件**: claude-code-guide に、次の3点を公式ドキュメントで確認させ、回答（出典 URL 付き）を本 plan の「T0-4 前提確認」節に貼ってから着手する。(1) `Edit()` ルールのパス表記（プロジェクトルート配下だけを表す書き方）。(2) `Bash()` ルールの `*` が引数の途中で効くか（例: `Bash(bash scripts/*)`）。(3) deny が allow より優先されるか。
- **対象ファイル**: `.claude/settings.json`（`permissions` キーのみ）
- **変更内容**:
  - allow から削除: `Bash(bash *)`、`Bash(python3 *)`、`Edit(**)`
  - allow に追加: `Bash(bash scripts/*)`、`Bash(bash .claude/hooks/*)`、`Bash(python3 scripts/*)`、`Bash(uv run pytest *)`、プロジェクトルート配下だけを表す Edit ルール（表記は前提確認の結果に従う）
  - deny を新設: `Bash(git push --force*)`、`Bash(git push -f*)`、`Bash(git push * main)`、`Bash(git push * HEAD:main)`、`Bash(gh pr merge *)`、`Read(./.env)`、`Edit(./.claude/settings.json)`、`Write(./.claude/settings.json)`、`Edit(./.codex/hooks.json)`、`Write(./.codex/hooks.json)`（パス表記は前提確認の結果に合わせる）
  - 上記以外の allow 項目は変更しない。
- **してはいけないこと**: `hooks` キーを変更しない（T0-5 の担当）。`templates/settings.json` を変更しない。`curl` を deny しない（`pm.md` の Slack 送信が使っている）。
- **検証コマンド**: `jq -e '.permissions.allow | index("Bash(bash *)") == null and index("Bash(python3 *)") == null and index("Edit(**)") == null' .claude/settings.json` → `true`。`jq '.permissions.deny | length' .claude/settings.json` → 10。`jq empty .claude/settings.json` → エラーなし。

**T1-1 run 契約スキル**
- **complexity**: M / **risk_level**: medium
- **目的**: unattended run がどのハーネスで起動されても同じ振る舞いをするための手順書を、正本1箇所（ADR-012）に置く。
- **対象ファイル**: `.agents/skills/always-on/SKILL.md`（新規）
- **変更内容**: 次の節を持つ SKILL.md を作る（frontmatter の `name: always-on`、`description` は「スケジュール実行などで owner 不在のまま起動された run が従う契約」）。
  1. **run の定義と禁止事項**: ADR-019 D3 の6項目を、そのまま箇条書きで転記する。
  2. **入力の読み方**: 読むもの（open な Issue と PR、main ブランチの `.claude/_queue.json`）と、ハーネス別の操作対応表（Claude Code クラウド: GitHub MCP の `list_issues`・`list_pull_requests`・`add_issue_comment`／ローカル・Codex: `gh issue list`・`gh pr list`・`gh issue comment`）。
  3. **出力の書き方**: 出力先は owner-inbox Issue（本文マーカー `<!-- agent-crew:owner-inbox -->` を持つ open な Issue。マーカーで探し、タイトルで探さない）。1 run につきコメントは最大1件。報告する項目が0件ならコメントしない。
  4. **停止条件と needs-owner**: D3-4/5 の条件に当たったら、作業を止めて owner-inbox に1件コメントし、push 通知を出させるために「needs-owner」という語を run の最終応答の先頭に置く。
  5. **timer 一覧へのリンク**: `timers.md`
- **してはいけないこと**: `.claude/skills/` にコピーを置かない（正本は一箇所）。既存スキルを変更しない。
- **検証コマンド**: `test -f .agents/skills/always-on/SKILL.md && rg -c '^## ' .agents/skills/always-on/SKILL.md` → 5。`rg -n 'owner-inbox' .agents/skills/always-on/SKILL.md` → 1件以上。
