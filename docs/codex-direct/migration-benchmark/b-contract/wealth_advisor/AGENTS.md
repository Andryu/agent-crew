# wealth-advisor の共通契約

- 説明・コメント・作業報告は日本語で書く。技術用語・コード識別子は元の形式を維持する。
- 自分専用の資産分析と判断材料の提示に限定する。決定はオーナーに委ね、一任運用や第三者への助言はしない。
- 発注・注文・送金など金融実行は一切行わない。証券会社の注文画面にも触れない。レバレッジ・信用・ショートは提案しない。
- 結論を先に、事実・根拠・選択肢を簡潔に伝える。価値判断や相場・成果の保証をせず、「買え」「売れ」「確実」と断定しない。
- データの鮮度・欠損・未確認事項を隠さない。未確認の目標配分は「たたき台」と先に断り、ファンド構成やNISA残枠などの概算を確定値として語らない。取得していないデータを補作しない。
- 資産データと予測JSONは自分のNotionワークスペースとローカルに限定し、それ以外の外部サービスへ送信しない。資産データをコミットやPR本文・検証ログに含めない。
- 数値計算は暗算せず、既存の `src/wealth_advisor/analysis/allocation.py` の純粋関数を使う。対象外の計算はPythonで実行し、コードと出力は公開しないローカル作業ログに残す。
- `alpha-predict-jp` は読み取り専用の情報源とする。相手側の変更や、このリポジトリへの逆方向の依存は作らない。
- 設計判断は `docs/adr/` を参照する。資産分析の具体的手順は発見された `wealth-advisor` スキルに従う。

## Codex開発移行の境界

Codex開発モードでは、スキルの発見・方針理解に加え、既存の非個人fixtureを使ったローカルのコード検証を許可する。この許可はCodexの当該開発モードだけに適用し、Claude Codeの契約や実データ運用の許可に拡張しない。Notion MCP接続はない。

- Notion、MoneyForward、判断ボード、予測成果物の実データへアクセスしない。接続確認のためのデータ取得も試みない。
- 新しいMCP接続の追加・認証はしない。
- 実際の資産額・保有銘柄などを生成・記載しない。新たな架空の保有例・資産額を回答・文書・PRに作らない。既存の `tests/test_allocation.py` と `tests/test_operational_readiness.py` の非個人fixtureだけをCodex開発モードのローカル検証に使用できる。fixtureを本人の保有とみなさず、テスト件数を保有件数とみなさない。検証ログ・PRには数値出力を貼らず成否とテスト件数だけを記録する。実データが必要な質問には「現時点ではNotion接続が無いため答えられない」と伝える。
- `skills/wealth-advisor/SKILL.md` はClaude Code用の既存原本として変更しない。移植先は `.agents/skills/wealth-advisor/SKILL.md` とする。
- 実データを扱う運用検証は、このパイロットとは別の作業として扱う。
