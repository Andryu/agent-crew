# fable-class

このskillは判断と検証を明確にするための作業ガイドである。モデル名、provider、担当者、委譲先を固定しない。オーナーが指定した実行方法と承認済みの範囲を優先する。

## 適用

complexity M以上、risk medium以上、または複数の有力な代替案を持つ重要な設計判断に使う。単純な文言・整形・局所修正では関連検証だけを行えばよい。ファイル数だけでriskを決めない。

1. 要求、現状、制約を実ファイルとGitで確認する。既存の未追跡・他セッションの変更を保持する。
2. 対象が適用条件を満たすときは、`docs/plans/<日付>-<slug>.md`に短いSPEC/PLAN、代替案と選択理由、完了条件、検証方法を記録する。詳しくは[planning.md](references/planning.md)。重要な設計判断は確定前に独立反証を行う。
3. 通常はメインが調査・設計・実装・関連テストを進める。独立して進められる作業で委譲が有益、またはオーナーが指定した場合に委譲する。詳しくは[delegation.md](references/delegation.md)。
4. 検証を実施し、結果と未検証範囲を記録する。権限、外部副作用、データ送信境界、後方互換性、金融計算の意味を変える変更は、別々の新規コンテキストで仕様準拠と品質をレビューする。詳しくは[verification.md](references/verification.md)。

queue、外部操作、hook、通知の権限境界はrepoの`AGENTS.md`を正本とする。過去のADRや計画は経緯であり、現在の実行経路を強制しない。
