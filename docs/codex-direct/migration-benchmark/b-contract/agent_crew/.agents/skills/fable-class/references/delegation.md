# 委譲

通常はメインが調査・設計・実装・関連テストを行う。オーナーが担当を指定した場合、または独立した作業を並行化でき、引継ぎと統合の費用に見合う場合に委譲する。特定のモデル、Herdr、外部APIを既定にしない。

委譲時は目的、所有するファイルや責務、受入条件、関連する制約、検証方法を渡す。他者も同じ作業ツリーを使う場合はその旨を伝え、他者の差分を戻さないよう明示する。委譲先の結果はGit差分と検証結果で受け取り、メインが統合と最終判断を担う。

対象外の差分を検出したら、まず所有者と意図を調べる。自分の依頼による追加変更なら理由を確認し、採否を決める。別セッションの変更は保持して報告する。差分を機械的に破棄しない。外部送信・公開・Issue操作などは、その操作に対する承認範囲を確認する。
