## 0. 前提と本書のスコープ判断

- **ターゲット**: B「元TD世代（30代中心）」主＋C「AIネイティブ層」拡散役（product-design 2.1、確定）
- **操作語彙は4つ**: 置く／売る／ウェーブ開始／速度×2（product-design 3節の剪定案を採用）。**塔アップグレード・能動スキル「発熱」・早出しボーナスはv1画面に含めない**。理由と代替案は「## 9. 削ってはいけない所／削れる所」で述べる

- 上記はチームリードの指示文中の確定方針に従った判断。product-design.md自体はまだ☐（オーナー未確定）のため、末尾で明示的に要確認点として返す

## 1. ユーザーフロー

### 1.1 全体フロー

```
[タイトル]
  │  （挑戦状ハッシュあり）→ 「挑戦状が届いています」表示 → 「この条件で始める」/「通常ではじめる」
  ↓ 「はじめる」タップ
[playing: 配置フェーズ（ウェーブ1）]
  │  初回のみ吹き出し「塔を置いて、ウェーブ開始」
  ↓ 塔を1つ以上配置（0でも進行可） → 「ウェーブ開始」
[playing: ウェーブ進行中]
  │  全個体が撃破 or 到達
  ↓ evolve() 実行
[playing: 変異レポートmodal]
  │  「とじる」
  ├─ wave < 15 → [playing: 配置フェーズ（次ウェーブ）] ループ
  ├─ wave === 15 クリア → [result: クリア]
  │     └─ 「エンドレスで続ける」→ [playing: 配置フェーズ（wave16〜）] ループ継続
  └─ lives === 0（進行中いつでも）→ [result: ゲームオーバー]
       ↓
[result] → 「アンケートに答える」→ [survey] → 「タイトルへ」→ [タイトル]
       └─ 「もう一度あそぶ」/「エンドレスで続ける」以外のボタンなら → [タイトル]
```

### 1.2 「最初の30秒」秒単位設計

離脱計測点: **ウェーブ2開始率**（配置フェーズ2回目に到達した割合をlocalStorageに記録）。ウェーブ1終了までに「約束」が可視化されるかがこの数値を左右するため、以下の秒割りを設計の基準値とする（実測は許容誤差込み）。

| 時刻 | 画面状態 | 見えるもの | ユーザーの操作 |
|---|---|---|---|
| 0.0s | タイトル | ロゴ「群変」＋一文コピー「群れは、あなたの守り方に合わせて進化する。」＋「はじめる」ボタンのみ | ボタンを見る |
| 0.0-2.0s | タイトル | （挑戦状ハッシュがあれば）バナー表示。無ければ即操作可 | 「はじめる」タップ |
| 2.0s | 配置フェーズ開始 | 盤面（3レーン・空）、塔パレット（好中球のみ・残り3枠は🔒）、資金300G／ライフ20／WAVE 1/15。**次ウェーブ・プレビューは非表示**（wave1のみ簡素化） | 吹き出し「塔を置いて、ウェーブ開始」が塔パレット付近に出現 |
| 2.0-12.0s | 配置フェーズ | プレイヤーが好中球を1〜3個配置（配置ごとに配置音） | 塔パレットタップ→セルタップを繰り返す |
| 12.0s前後 | — | 最初の配置操作で吹き出しはフェードアウト（最大でも8秒でタイムアウト消去） | — |
| 12-16s | 配置フェーズ | 「ウェーブ開始」ボタンが常時目に入る位置（盤面下） | 「ウェーブ開始」タップ |
| 16-40s | ウェーブ進行中 | 個体が0.4秒間隔で出現、塔が自動攻撃、撃破粒子・数字ポップ | 任意で速度×2、追加配置・売却 |
| 40-55s | ウェーブ終了 | evolve実行（体感ラグなし、即座に） → 変異レポートmodal表示。初回のみ冒頭に「群れは、あなたの守り方に合わせて変わります」 | 3行を読む → 「とじる」 |
| 55-60s | 配置フェーズ（ウェーブ2） | **ここで初めて次ウェーブ・プレビュー「次に来る群れ」が出現**（スライドイン） | この時点でウェーブ2開始率を計測対象として記録 |

60秒以内に「約束（群れが変わる）」を1回体感させることを最優先の指標とする。ウェーブ1は必ず勝てる設計（デザイン仕様書D1-3）のため、上記タイムラインの障害はUI理解の遅さのみに限定される。

### 1.3 状態遷移の網羅（正常系・異常系）

```
[タイトル]
  ├─ 通常はじめる → 配置フェーズ(wave1, seedランダム)
  ├─ 挑戦状あり・この条件で始める → 配置フェーズ(wave1, seed/gold=ハッシュ由来)
  └─ 挑戦状あり・通常ではじめる → ハッシュ破棄→ランダムseedで開始

[配置フェーズ]
  ├─ 塔パレットタップ → 選択状態（射程プレビュー円が追従）
  │    ├─ 有効セルタップ → 配置成功（配置音、資金減算）→ 選択解除
  │    ├─ レーン上セルタップ → 拒否（赤フラッシュ0.15s、選択継続）
  │    ├─ 資金不足で選択自体不可 → パレットアイコンがグレーアウト（タップ自体無効）
  │    └─ 盤面外/他パレットタップ → 選択解除
  ├─ 配置済み塔タップ → 「売る (+◯G)」フローティングボタン表示
  │    ├─ 「売る」タップ → 売却成功（配置音を低ピッチ再生、資金加算）
  │    └─ 他の場所タップ → パネルを閉じるのみ（売らない）
  └─ 「ウェーブ開始」タップ → ウェーブ進行中へ

[ウェーブ進行中]
  ├─ 全個体を撃破 or 全個体が到達 → ウェーブ終了 → evolve → 変異レポートmodal
  ├─ 「×2」タップ → 速度倍率トグル（進行中のみ有効。レポート表示中は自動でOFF相当に戻る）
  ├─ 配置・売却は継続して可能（誤操作防止フィードバックは配置フェーズと同一仕様）
  └─ lives === 0 に到達した瞬間（撃破処理中でも即座に） → result(ゲームオーバー)へ強制遷移

[変異レポートmodal]
  └─ 「とじる」以外のUIは全て無効化（モーダル背後をdim、盤面操作不可）
      ├─ wave到達数が15未満 → 配置フェーズ（次ウェーブ）
      └─ wave===15到達 → result(クリア)

[result]
  ├─ クリア: 「エンドレスで続ける」→ 配置フェーズ(wave16)へ復帰（プレビュー等の全UI継続）
  ├─ クリア/ゲームオーバー共通: 「この条件で挑戦状を送る」→ クリップボードコピー＋トースト「コピーしました」
  ├─ 「アンケートに答える」→ survey
  └─ 「タイトルへ」/ アンケートスキップ → タイトル（bestWave更新はresult到達時点で確定済み）
```

## 2. 1画面レイアウト（ワイヤーフレーム）

盤面は論理解像度576×384（3:2）。**UIは全て盤面の外周に寄せ、盤面自体は縮小・分割しない**（配信映え・可読性維持のため）。

### 2.1 PC横（デスクトップ・マウス+キーボード）

```
┌──────────────────────────────────────────────────────────────────┐
│ 300G   ♥20   WAVE 3/15                                    [🔊]    │ ← 上部バー 高さ36px
├────────────────────────────────────────────────┬──────────────────┤
│                                                  │  次に来る群れ     │
│                                                  │                  │
│                                                  │   ◯ ◎ ◇ ◯ ◎    │ ← 静止・見た目のみ5体
│               盤面 576×384                       │  （wave2以降のみ）│
│         （3レーン・横一直線・空セルは薄グリッド）    │                  │
│                                                  │                  │
│                                                  │                  │
├──────────────────────────────────────────────────┤                  │
│ [好中球 50G][マクロファージ 100G][🔒5][🔒7]  [ウェーブ開始] [×2]      │
└──────────────────────────────────────────────────┴──────────────────┘
  ← 塔パレット（横並び、選択中は枠強調）                 ↑ 速度トグルは
                                                           wave進行中のみ活性
```

- 塔パレットはテキストラベルなし。アイコン（属性別の形状差、後述4章）＋コスト数字のみ
- 未解禁枠は🔒＋解禁ウェーブ数字（例「5」）を小さく重ねる。タップ無効
- PCショートカット: `1`〜`4` で解禁済み塔を選択（未解禁キーは無反応。反応なしのフィードバックも出さない＝存在しないものとして扱う）、`Esc` で選択解除、`Space` でウェーブ開始（配置フェーズのみ）、`Tab` で速度×2トグル（進行中のみ）
- 次ウェーブ・プレビューはwave1配置フェーズには表示しない（右カラムは空白のまま、または盤面幅を一時的に広げる）。wave2以降でスライドイン

### 2.2 スマホ縦（タップのみ）

```
┌─────────────────────┐
│ 300G ♥20 W3/15  [🔊] │ ← 上部バー（高さ圧縮）
├─────────────────────┤
│                       │
│    盤面（幅いっぱい・   │ ← 576:384比率を維持したままレターボックス
│     3:2比率を維持）     │
│                       │
├─────────────────────┤
│ 次に来る群れ ◯◎◇◯◎   │ ← 帯（高さ40px）。タップで全画面シートに拡大表示
├─────────────────────┤
│[好中球][🔥][🔒][🔒]   │ ← 塔パレット（アイコンのみ、横スクロール不要な4枠固定）
│  [ ウェーブ開始 ]  [×2]│
└─────────────────────┘
```

- 塔選択→セルタップで配置（PC同様、射程円が選択中の塔に追従）
- 配置済みタップ→「売る」ボタンが対象セルの直上にポップアップ（指で隠れないよう上方向優先、画面上端に近い場合は下方向に自動反転）
- 誤操作時の振動フィードバック（`navigator.vibrate`対応端末のみ）: レーン上配置拒否・資金不足時に短振動50ms。iOSは非対応前提で視覚フィードバックを常にプライマリとする
- 次ウェーブ・プレビューの帯タップで拡大表示は必須ではない任意強化。実装コストが厳しい場合は帯のみ（5体を小さく並べるだけ）で成立するため優先度は低（##9参照）

| 操作 | 開始トリガー | 完了トリガー | PC | スマホ |
|---|---|---|---|---|
| 置く | 塔パレットの解禁済みアイコンをタップ | 有効セルをタップ | クリック→クリック（または数字キー→クリック） | タップ→タップ |

**塔種の選択は「置く」の内部手順であり、新たな語彙としては数えない**（何を置くかは置く操作の一部）。

### 誤操作防止フィードバック一覧

| 状況 | フィードバック | 状態の変化 |
|---|---|---|
| レーン上セルへ配置しようとした | セルが赤く0.15秒点滅＋振動50ms（対応端末） | 選択状態は継続（すぐ再試行できる） |

| 未解禁の塔アイコンをタップ | 🔒表示のためタップ判定なし | — |

## 4. 教えない導入

### 4.1 初回吹き出し

- 表示条件: `storage.js` の `seenIntro` が未設定の初回プレイのみ、配置フェーズ（wave1）開始と同時
- 文言: **「塔を置いて、ウェーブ開始」**（1つだけ。矢印やハイライト枠は使わず、吹き出し自体が塔パレット付近から生えている形で十分な誘導とする）
- 消滅条件: プレイヤーが最初の配置操作を行った瞬間に即フェードアウト（0.3秒）。操作しない場合は8秒でタイムアウト消去。以後二度と出さない（`seenIntro: true` を即時保存）
- これ以外のツールチップ・ヘルプアイコン・チュートリアルモーダルは**一切置かない**

### 4.2 塔の段階解禁（ウェーブ1/3/5/7）

説明文は出さない。解禁の瞬間（該当ウェーブの配置フェーズに入った瞬間）に、パレット内の該当スロットが🔒アイコンから塔アイコンへクロスフェード（0.4秒）し、そのアイコンだけ2秒間ごく弱いパルス（拡大縮小±5%）で注意を引く。以後パルスは止まり通常表示。

- reduced-motion時: パルスなし。クロスフェードのみ（またはフェードも省略し即切替＋0.6秒だけ枠線を強調表示）

これにより「新しい塔が来た」ことはアイコンの変化そのもので伝わり、テキストは不要と判断する（PvZの「絵が機能を説明する」原則）。

## 5. 変異レポートmodal

3秒で読める分量を上限とする。読了に必要な文字数の目安として、見出し込みで最大120字程度に収める（3行×最大30字程度＋見出し）。

```
┌──────────────────────────────┐
│           第3世代の記録           │
│                                  │
│   （代表個体・変化前）→（変化後）  │  ← 図形の並置比較。矢印は装飾でなく変化の向きを示す
│                                  │
│  ・群れは高速化した（+12%）        │
│  ・抗体への耐性を持つ個体が増えた   │
│    （15%→40%）                   │
│                                  │
│            [ とじる ]             │
└──────────────────────────────┘
```

- 代表個体の選定: `evolution.js` の `summarize` から算出した平均遺伝子に最も近い個体1体を前世代・今世代それぞれから選び、静止した図形として並べる（速度=縦横比、体力=輪郭太さ、耐性=色+形状記号、体格=半径がそのまま比較できる）
- 変化なし（全項目が閾値未満）の場合: 1行のみ「群れに目立った変化はない」。図形比較は表示する（変化がないことも視覚的に確認できるようにする）
- **初回（wave1終了後）だけ**、見出しの下に追加の1行を挿入: 「群れは、あなたの守り方に合わせて変わります」（本文の変化リストより上、視覚的に区別できる弱いハイライト背景）
- 「とじる」ボタンのみが唯一の操作（1画面1アクション）。モーダル外クリックでは閉じない（誤タップで読み飛ばさせない意図的な設計）

## 6. 敵の見た目直結の可読性（色覚多様性対応）

色だけに依存しない冗長符号を、耐性（resist）と塔の両方に付与する。

### 6.1 敵の耐性マーカー

| resist | 色 | 追加の形状符号 | 意図 |
|---|---|---|---|
| 0 none | `#9a9a9a` 灰 | マーカーなし（無地の円） | 基準状態、装飾を増やさない |
| 1 heat | `#e05a3a` 赤橙 | 個体中心に▲（上向き三角、輪郭のみ） | 炎の連想、頂点が尖った形は小サイズでも識別しやすい |
| 2 cold | `#4aa8e0` 青 | 個体中心に◇（菱形/結晶片、輪郭のみ） | 氷結晶の連想 |
| 3 bolt | `#e6c94a` 黄 | 個体中心にジグザグ線（稲妻、輪郭のみ） | 電撃の連想、直線基調で最小サイズでも視認可 |

マーカーは輪郭線のみで塗りつぶさず（個体本体の塗り色を覆わない）、サイズは半径の約40%。個体の塗り色の明度に応じてマーカー線色を白/黒に自動反転し、コントラストを確保する。

### 6.2 塔の属性差（色に加えた形状差）

| 塔 | 色 | 形状差 |
|---|---|---|
| 好中球（none） | 薄灰 `#e8e8e8` | 正円のみ、装飾なし |
| マクロファージ（heat） | 赤橙 | 円の外周に短い棘6本（放射状） |
| インターフェロン（cold） | 青 | 円の外周に六角結晶の枠線 |
| 抗体（bolt） | 黄 | 円の外周にジグザグの輪郭 |

**塔の形状記号と、その塔が対抗しづらい耐性個体のマーカー記号を意図的に揃える**（heat塔=棘/heat耐性個体=▲、cold塔=結晶/cold耐性個体=◇、bolt塔=ジグザグ/bolt耐性個体=ジグザグ）。テキストなしでも数プレイの反復で「この形の塔とこの形の敵は相性が悪い」という関連づけが自然に育つことを狙った設計判断。

### 6.3 凡例の扱い

**常設の凡例は置かない**（判断・理由）。盤面を主役にする方針、およびPvZ由来の「テキストで教えない」原則を優先するため。色以外の形状符号を全個体・全塔に付与していること自体が色覚多様性への実質的な対応であり、凡例なしでも「同じ形は同じ性質」という学習は成立する。変異レポートの前後比較（##5）が反復的に「この形が増えた/減った」という気づきを与えるため、凡例の代替として機能する。

```
└──────────────────────────────┘
```

- 添え書きの生成ルール: 「第{世代数}世代・速度×{speedMean を小数1桁}・{resistShare最多の属性名}耐性」。resist最多がnone（無耐性が多数派）の場合は耐性の句を省略し「第9世代・速度×1.6」のみとする
- 代表個体はゲームオーバー時点で盤面に残っていた個体のうちfitness最上位1体（撃破されず到達 or 到達間際だった個体）。スクリーンショットしたくなるよう、背景は暗めに落とし個体だけを際立たせる

### 7.2 クリア（wave15到達）

```
┌──────────────────────────────┐
│           防衛完了               │
```

## 8. フィードバック（撃破・被害・SE）

| イベント | 視覚 | SE | reduced-motion時の代替 |
|---|---|---|---|
| 塔の配置成功 | セルに配置アニメ（0.15秒スケールイン） | 配置音 | スケールインを省略し即表示 |
| 塔の売却成功 | セルがフェードアウト（0.15秒） | 配置音を低ピッチ再生（新規SEは追加しない） | フェードを省略し即消去 |

| 塔の段階解禁 | パレットアイコンのパルス（##4.2） | なし | パルスなし、枠線強調のみ |

## 9. 削ってはいけない所／削れる所

### 削ってはいけない（テーゼ「進化が知覚されるか」の土台）

| 要素 | 理由 |
|---|---|
| 3レーン固定・1画面盤面 | 状況把握の速さそのものがUXの土台。迷路化・複数画面化はテーゼと無関係にコストだけ増やす |
| 遺伝子→見た目直結＋色以外の形状符号 | 「進化が見える」の中核。ここを削るとレポートを読むしかなくなり知覚が弱まる |
| 変異レポートmodal（3行以内・閾値ロジック・初回一行） | 「読んだ上で配置を変える」導線の起点。閾値ロジックがないと毎回変化ありに見えて信頼を失う |
| 次ウェーブ・プレビュー | 進化を「事後」だけでなく「事前の脅威」として見せる、知覚への寄与が最大の1手（人気TD分析P1） |
| 負けた画（ゲームオーバー画面の代表個体表示） | スイカの「溢れる瞬間」に相当する唯一の失敗演出。ここが弱いと負けが単なる終了になる |
| 教えない導入（吹き出し1つ＋段階解禁） | 説明画面ゼロを実現する最小限の代替手段。これ自体を削ると学習コストが操作語彙にすべて跳ね返る |
| 操作語彙4つとその誤操作防止 | スイカの物差し「直感操作」に対応する最後の砦。ここを増やすと他の全項目の効果が薄まる |
| チャレンジリンク | 部門共通の「届け方」検証点。プロダクトデザインの届け方の武器はこれのみ |
| アンケート設問2 | 部門固有の成功指標そのもの。削れば検証ができない |

### 削れる（v1.5以降でよい）

| 要素 | UX観点の意見 |
|---|---|
| 塔アップグレード2段階 | **削って良い**。配置済み塔タップ時のフローティングパネルが「売る」だけでなく「強化/売る」の2択になり、既存塔の状態（Lv1/2/3）を常時表示する必要も生まれる。1画面1アクション原則がやや崩れ、初回プレイの学習コストが上がる。進化知覚への寄与も間接的（P4「応える」であって「見せる/読ませる」ではない）。初回テストで「対抗手段が足りない」という声が出てから追加するのが妥当 |
| 能動スキル「発熱」 | **削ってよいが、v1.5復活の最有力候補**。ボタン1つ＋レーン選択1回のみで完結し、ネストしたUI状態を増やさない（アップグレードほどコストが高くない）。かつオーナー指摘「介入が薄いのは微妙」への直接回答になる。実プレイで「置いて眺めるだけ」という声が出た場合、真っ先にこれを戻すことを推奨する |
| 早出しボーナス | **削って良い**。「なぜ+15なのか」「いつ発生したか」を一瞬しか見せられず、テキストなしでは概念が伝わりにくい。視認性投資に対して効果が薄い。テンポの速いプレイヤーへの報酬はウェーブ進行の難易度カーブ自体で十分に足りる |

## 補足: ゼロ状態・エッジケース

- **wave1配置フェーズの盤面**: 塔0個の状態が初期状態そのもの。レーンセルと配置可能セルは初期状態から視覚的に区別する（レーン=進行方向を示す模様入りの帯、配置可能セル=薄いグリッド線のみ）。テキストでの説明を代替する最重要のゼロ状態
- **中断・再読み込み**: ゲーム内状態（配置・進行中ウェーブ）は保存対象外（`storage.js` は bestWave / survey / challengeReceived のみ）。リロードするとタイトルに戻る。これは仕様書通りの割り切りであり、本書もこれを前提にする（オートセーブは実装しない）
- **リサイズ**: canvasはCSSで論理解像度576×384を画面幅に合わせて拡大縮小する前提（デザイン仕様書通り）。UI要素（パレット・ボタン）はリサイズ時に再レイアウトせず、盤面と一体でスケールする
- **同時多数撃破**: SEが飽和しないよう約40ms間隔でクランプ（##8）。粒子・数字ポップは個体ごとに独立して描画してよい（描画負荷は50体上限のため許容範囲）

## Rikuへの実装時の注意点（先出し）

1. 塔パレット・耐性マーカーの形状差（##6）はrenderer.jsの個体・塔描画に直結する。色定義と同じ場所（config.js）に形状記号の定義もまとめておくと変更に強い
2. 変異レポートmodalの代表個体選定（平均遺伝子への最近傍）は`evolution.js`の`summarize`が返す平均値から算出できるが、個体プール自体（前世代・今世代のgenome配列）を保持しておく必要がある。`game-state.js`の`lastSummary`だけでなく、比較用に前世代population（またはその代表1体）を残す設計にすること
3. wave1配置フェーズだけ次ウェーブ・プレビューを非表示にする分岐を忘れないこと（##2.1、##1.2で明記）
4. 操作語彙4つ以外のUI（アップグレードボタン・スキルボタン・早出し表示）は本書では意図的に設計していない。もしオーナー判断でこれらがv1に戻る場合は本書の追補が必要（##末尾の矛盾点を参照）
